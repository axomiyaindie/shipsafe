
# Code of Conduct

## Our Pledge

We are committed to making participation in the ShipSafe community a welcoming, respectful and positive experience for everyone.

ShipSafe is an open-source application security knowledge base and toolkit. We believe that sharing knowledge, collaborating responsibly and learning from one another help make software safer.

We welcome contributions from people of all experience levels, backgrounds and professional disciplines.

We pledge to make participation in our project a harassment-free experience for everyone, regardless of age, disability, personal background, experience level, nationality, appearance or identity.

## Our Standards

Examples of behavior that contribute to a positive environment include:

- Being respectful and considerate.
- Welcoming different viewpoints and experiences.
- Providing constructive feedback.
- Accepting responsibility for mistakes.
- Focusing on what is best for the community.
- Supporting newcomers and first-time contributors.
- Sharing knowledge in a helpful and accessible way.
- Giving credit to original authors and contributors.
- Discussing technical disagreements professionally.
- Following responsible security research practices.

Examples of unacceptable behavior include:

- Harassment, intimidation or personal attacks.
- Discriminatory or derogatory comments.
- Threats or deliberate intimidation.
- Publishing another person's private information without permission.
- Unwelcome sexual attention or advances.
- Trolling, insulting or deliberately disruptive behavior.
- Repeatedly disrupting constructive discussions.
- Deliberately misrepresenting another contributor's work.
- Encouraging unauthorized attacks against third-party systems.
- Sharing private credentials, secrets or confidential information.

## Technical Discussions and Disagreements

ShipSafe encourages critical technical discussion.

Contributors may disagree about security recommendations, implementation choices, architecture, tooling or documentation.

Such disagreements should remain professional and evidence-based.

When discussing security matters:

- Focus on technical facts and reproducible evidence.
- Explain the reasoning behind recommendations.
- Reference authoritative sources where possible.
- Distinguish opinions from established security guidance.
- Accept corrections when evidence demonstrates an error.
- Avoid personal criticism or hostile language.

A disagreement about technical implementation is not an excuse for disrespectful behavior.

## Responsible Security Collaboration

Because ShipSafe focuses on application security, contributors are expected to act responsibly when discussing vulnerabilities and security research.

Community members should:

- Respect responsible disclosure practices.
- Avoid exposing real credentials or private information.
- Never encourage unauthorized access to systems.
- Avoid publishing confidential vulnerability details prematurely.
- Respect the privacy and security of others.
- Follow the project's [Security Policy](SECURITY.md).

## Scope

This Code of Conduct applies to all spaces associated with the ShipSafe project, including:

- GitHub issues.
- Pull requests.
- GitHub discussions, where available.
- Project documentation and contributions.
- Official project communication channels.
- Other spaces where someone is officially representing ShipSafe.

## Enforcement Responsibilities

Project maintainers are responsible for clarifying and enforcing this Code of Conduct.

They may take appropriate action in response to behavior they consider inappropriate, threatening, offensive or harmful.

Maintainers may:

- Request that a contributor modify their behavior.
- Remove inappropriate comments or content.
- Close discussions that become abusive or disruptive.
- Temporarily restrict participation.
- Remove a contributor from project spaces when necessary.

Actions should be proportionate to the behavior and its impact on the community.

## Reporting Issues

If you experience or witness unacceptable behavior, report it privately to the project maintainers.

Use an appropriate private GitHub communication channel associated with the repository.

Do not create a public issue containing private information or sensitive details about the incident.

When reporting an issue, include:

- A description of the behavior.
- Relevant links or references.
- The approximate date and context.
- Any supporting evidence you can safely provide.

Reports will be handled as responsibly and confidentially as practical.

Maintainers should avoid disclosing reporter information without an appropriate reason.

## Responsibilities of Maintainers

Project maintainers are expected to:

- Apply this Code of Conduct consistently.
- Treat reports seriously.
- Avoid retaliation against people who report concerns in good faith.
- Protect confidential information where reasonably possible.
- Explain moderation decisions when appropriate.
- Encourage constructive participation.
- Set a positive example for the community.
